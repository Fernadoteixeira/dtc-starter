09 · Conventions & Guardrails

How this codebase wants to be edited.

Straight from AGENTS.md — the rules a lint failure or a silent bug usually traces back to.
Code style
  • Backend must satisfy @medusajs/eslint-plugin's recommended config — a lint failure usually means the code is wrong, not just unformatted.
  • No semicolons. Double quotes, 2-space indent.
  • Files kebab-case; types/classes PascalCase; functions/variables camelCase; DB columns snake_case.
  • Backend routing is file-based — no manual router registration.
  • Business logic belongs in workflows, not route handlers.
Off-limits
  • .medusa/, .next/, dist/, out/, .turbo/ — build output, regenerated.
  • pnpm-lock.yaml — never hand-edit; change only via pnpm.
  • .env / .env.local — never commit, print or copy secret values.
  • Existing migrations in src/modules/*/migrations/ — add new ones, don't rewrite.
  • No destructive DB commands without explicit confirmation.
Common mistakes on this repo
  • Installing a dependency at the root instead of inside the app that needs it.
  • Editing a custom module's model without medusa db:generate — the migration silently never applies.
  • Calling the Medusa API from the storefront without NEXT_PUBLIC_MEDUSA_PUBLISHABLE_KEY.
  • Using Tailwind v4 syntax in nos-gallery — this codebase runs Tailwind v3.
  • Assuming Framer Motion or shadcn/ui are installed — they are not; use Radix UI and Headless UI directly.
  • Running tests without a reachable PostgreSQL instance.
