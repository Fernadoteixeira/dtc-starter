# Usage

1. Start with the outcome, not the skill name.
2. Select the smallest atomic skill set capable of producing the outcome.
3. Use one cross-domain orchestration when three or more domains must coordinate.
4. Preserve one authoritative artifact per decision.
5. Require Definition of Ready before execution and Definition of Done before closure.
6. Record evidence, ownership, rollout, rollback and review cadence.

## Recommended execution order

`strategy → discovery → definition → architecture → experience → engineering → validation → release → operations → learning → retirement`

This order is directional, not strictly linear. Feedback loops may return work to earlier domains.
